# Clawith 交互组件使用约定

依据 Ant Design 官方 Button、Modal、Drawer、Message 和 Form 文档整理。组件选用规则为本项目约定，不是引入另一套视觉主题；实际外观以 Clawith 已有全局 tokens、按钮和反馈组件为准。

| 需求 / 场景 | 组件 | 交互规则 | 桌面自动化的使用位置 |
|---|---|---|---|
| 打开另一项工作 | 页面导航 | 带上工作上下文；描述的是开始编写，就必须将规范交给聊天，不能只跳转 | 开始编写 → 聊天草稿 |
| 确认一个短任务，留在原场景 | Modal | 标题、短说明、一个主要操作；Esc / 关闭 / 焦点返回；不堆长教程 | 脚本入口、新建、发布分配 |
| 查看详情、编辑多项内容，并保留列表 | Drawer 或列表详情布局 | 保留选中项、明确保存；不要嵌套多个抽屉 | 流程库与源码、参数、版本详情 |
| 同一对象的平级视图 | Tabs | 共享当前流程；不能把先后步骤伪装成标签 | 录制、编辑、试运行、版本 |
| 必须按顺序完成的复杂任务 | Steps | 仅在顺序确有约束时使用；不能把 Agent 能推导的配置变成用户向导 | 不用于编写脚本入口 |
| 输入用户确实知道的信息 | Form | 问业务事实；系统已知、可推导的字段不重复询问 | 新建名称、必要业务输入 |
| 快捷执行动作 | Button | 本项目一般用 2–6 个汉字的动词短语；说明放正文或 tooltip；同一操作区一个主按钮 | 开始编写、复制规范、保存草稿 |
| 复制等短暂成功反馈 | Message/Toast 或原位 status | 成功后明确反馈；失败不要跳转、不要假成功 | 规范已复制 |
| 必须处理的失败 | Inline Alert | 放在出错上下文，说明可采取的下一步 | 加载失败、试运行诊断 |
| 任务仍在运行 | 状态 + 记录 / Progress | 真实状态来自执行回执；不弹反复确认，不伪造进度 | 试运行与记录 |
| 长说明和技术细节 | Collapse / details | 默认收起；主体只保留决策需要的信息 | 查看规范、SDK |
| 搜索和筛选 | Search / Select | 直接改变列表，保留当前详情；无结果提供说明 | 流程库 |

## 视觉一致性

- 使用 `--accent-primary`、`--accent-subtle`、`--bg-*`、`--text-*`、`--border-*` 和现有 radius；不为子功能定义绿色品牌色。
- 按钮复用 `.btn` / `.btn-primary` / `.btn-secondary`，不在页面内覆盖一套按钮皮肤。
- 不重复放置同一 CTA 的头部按钮、横幅和卡片；空状态可以提供同一操作的补充入口。
- 错误、运行、成功用语义状态色；深色主题也要验证，不用浅色背景搭浅色文字。
- 保存、提交、测试、发布是不同事实，反馈必须与实际结果一致。

## 官方依据

- [Button](https://ant.design/docs/spec/buttons/)：操作强调、层级、位置和标签。
- [Modal](https://ant.design/components/modal/)：需要留在当前页面的短任务与确认。
- [Drawer](https://ant.design/components/drawer/)：保留原上下文的详情和多项编辑。
- [Message](https://ant.design/components/message/)：用户操作的轻量反馈。
- [Form](https://ant.design/components/form/)：数据收集与校验。
